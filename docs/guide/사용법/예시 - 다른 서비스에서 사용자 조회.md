# 예시: 다른 서비스에서 사용자 조회하기 (Feign)

> 작성: 대진 · 기준: `dev` d6af869 · 최종 수정: 2026-10-16
> 대상: user-ms의 사용자 정보가 필요한 서비스 (delivery-ms 영은: 배송담당자 확인, order-ms 다울: Slack 멘션용 slackId)
> 이 문서는 **처음부터 끝까지 그대로 따라 만들 수 있는 예제**입니다. 패키지·클래스 이름은 팀 4계층 규칙에 맞춘 제안이니 각자 서비스에 맞게 바꿔도 됩니다.
> ✅ 3장 ①~⑥ 코드와 6.1·6.2 테스트를 dev 복사본에 **문서 그대로 붙여 넣고** 돌려 통과를 확인했습니다(6.1 2개, 6.2 3개). 6.3은 같은 Adapter로 실제 user-ms에 붙여 2개 통과(2026-10-16). `DeliveryService`·`DeliveryErrorCode`는 확인용으로 최소한만 만들었습니다.

## 0. 무엇을 만드나

**상황 A (delivery-ms):** MASTER가 배송에 담당자를 배정할 때, 그 사람이 정말 **배송담당자인지** user-ms에 물어보고, 아니면 거절합니다.
**상황 B (order-ms):** 주문 완료 Slack 알림에 주문자를 멘션하려고 **slackId**를 가져옵니다. 못 가져와도 알림은 보냅니다.

둘 다 user-ms의 **내부 API 하나**를 씁니다.

```
GET /internal/v1/users/{userId}      (user-ms, Gateway 거치지 않음, 외부에서는 404)

200 → { "id": "…", "name": "김배송", "role": "USER", "isDeliveryManager": true, "slackId": "U07ABCDEF1", "active": true }
404 → { "code": "USER_NOT_FOUND", "message": "사용자를 찾을 수 없습니다." }   ← 없거나 탈퇴·비활성 사용자
400 → { "code": "INVALID_INPUT", … }                                       ← UUID 형식 아님
```

**완성 그림**

```mermaid
flowchart LR
    subgraph delivery-ms
        C[Controller] --> F[Facade<br/>application]
        F --> P[[UserPort<br/>domain 인터페이스]]
        A[UserAdapter<br/>infrastructure] -. 구현 .-> P
        A --> FC[UserClient<br/>@FeignClient]
    end
    FC -- "Eureka로 user-ms 찾아<br/>GET /internal/v1/users/{id}" --> U[(user-ms)]
```

- **application·domain은 Feign을 모릅니다.** `UserPort`라는 인터페이스만 압니다.
- Feign과 HTTP DTO는 **infrastructure에만** 있습니다. 나중에 호출 방식이 바뀌어도 Adapter만 고치면 됩니다.

## 1. 준비 (서비스당 한 번)

```groovy
// delivery-ms/build.gradle
dependencies {
    implementation 'org.springframework.cloud:spring-cloud-starter-openfeign'
    implementation 'org.springframework.cloud:spring-cloud-starter-circuitbreaker-resilience4j'   // 빠뜨리면 CB 없이 동작

    testImplementation 'org.wiremock:wiremock-standalone:3.9.2'                                 // 6장 테스트용
}
```

```java
// delivery-ms/src/main/java/com/delivery/DeliveryMsApplication.java
@SpringBootApplication
@EnableFeignClients                       // com.delivery 아래 @FeignClient를 찾는다
public class DeliveryMsApplication { ... }
```

타임아웃(연결 1초·응답 2초), Circuit Breaker, 오류 해석, 사용자 헤더 전달은 **common이 자동으로** 붙입니다. 따로 설정할 것은 없습니다.

## 3. 파일별 코드

### ① `InternalUserResponse`: user-ms 응답 모양 그대로

```java
package com.delivery.infrastructure.client.user;

/** user-ms GET /internal/v1/users/{userId} 응답. 필드 이름이 JSON과 같아야 한다 (user-ms와의 계약) */
public record InternalUserResponse(
        UUID id,
        String name,
        String role,
        boolean isDeliveryManager,
        String slackId,
        boolean active
) {
}
```

- 필드 이름은 **JSON 키와 똑같이** 씁니다. `isDeliveryManager`를 `deliveryManager`로 바꾸면 값이 항상 `false`로 들어옵니다(오류도 안 남).
- 쓰지 않는 필드는 빼도 됩니다. 모르는 JSON 필드는 무시됩니다.

### ② `UserClient`: Feign 클라이언트

```java
package com.delivery.infrastructure.client.user;

@FeignClient(name = "user-ms")                         // Eureka에 등록된 이름. url은 쓰지 않는다 (쓰면 기동 실패)
public interface UserClient {

    @GetMapping("/internal/v1/users/{userId}")
    InternalUserResponse getUser(@PathVariable("userId") UUID userId);
}
```

- `@PathVariable("userId")`처럼 **이름을 꼭 적으세요.** 생략하면 환경에 따라 기동 오류가 납니다.
- 사용자 헤더(`X-User-Id`·`X-User-Role`)는 common이 자동으로 붙입니다. 내부 API는 헤더가 없어도 동작합니다.

### ③ `UserInfo`: 내 도메인이 쓰는 사용자 정보

```java
package com.delivery.domain.user;

/** 배송 도메인이 보는 사용자. user-ms 응답 전체가 아니라 필요한 것만 */
public record UserInfo(UUID id, String name, boolean deliveryManager, String slackId) {
}
```

- 응답 DTO(①)를 application·domain으로 그대로 올리지 않습니다. user-ms 응답이 바뀌어도 이 클래스와 위쪽 코드는 그대로 둘 수 있습니다.

### ④ `UserPort`: 조회 인터페이스

```java
package com.delivery.domain.user;

public interface UserPort {

    /** 활성 사용자면 값, 없거나 탈퇴·비활성이면 empty. user-ms 장애는 예외(RemoteServiceException·RemoteTimeoutException) */
    Optional<UserInfo> findActiveUser(UUID userId);
}
```

### ⑤ `UserAdapter`: Feign 호출 + 오류 변환

```java
package com.delivery.infrastructure.client.user;

import com.common.exception.UserErrorCode;
import com.common.remote.RemoteBusinessException;
import com.common.remote.RemoteCallTemplate;
import com.delivery.domain.user.UserInfo;
import com.delivery.domain.user.UserPort;

@Component
@RequiredArgsConstructor
public class UserAdapter implements UserPort {

    private static final String TARGET = "user-ms";      // 예외·로그에만 쓰임
    private final UserClient userClient;
    private final RemoteCallTemplate remote;              // common이 빈으로 등록해 둠

    @Override
    public Optional<UserInfo> findActiveUser(UUID userId) {
        try {
            InternalUserResponse r = remote.execute(TARGET, () -> userClient.getUser(userId));
            return Optional.of(new UserInfo(r.id(), r.name(), r.isDeliveryManager(), r.slackId()));
        } catch (RemoteBusinessException e) {
            if (e.getErrorCode() == UserErrorCode.USER_NOT_FOUND) {   // 404 "없음"은 오류가 아니라 empty로
                return Optional.empty();
            }
            throw e;                                                   // 400 등 그 밖의 거절은 그대로
        }
    }
}
```

- **`remote.execute(...)`로 꼭 감싸세요.** 감싸지 않으면 Feign 예외가 그대로 나와 실패 종류를 구분할 수 없습니다.
- `USER_NOT_FOUND`는 common에 등록된 오류 코드라 `==`로 비교됩니다.
- 조회만 하므로 `executeWithRetryOnce`(실패 시 1번 더)를 써도 됩니다. 다만 user-ms가 느릴 때는 응답 시간이 최대 2배가 됩니다.

### ⑥ 쓰는 곳: 상황 A (delivery-ms, 담당자가 아니면 막기)

```java
package com.delivery.application.service;

@Service
@RequiredArgsConstructor
public class DeliveryAssignFacade {           // @Transactional 없음: 원격 호출은 DB 트랜잭션 밖에서

    private final UserPort userPort;
    private final DeliveryService deliveryService;   // 저장은 여기서 @Transactional

    public void assignManager(UUID deliveryId, UUID managerId, UUID actorId) {
        UserInfo manager = userPort.findActiveUser(managerId)
                .orElseThrow(() -> new BusinessException(DeliveryErrorCode.DELIVERY_MANAGER_NOT_FOUND));
        if (!manager.deliveryManager()) {
            throw new BusinessException(DeliveryErrorCode.NOT_DELIVERY_MANAGER);
        }
        deliveryService.assignManager(deliveryId, managerId, actorId);
    }
}
```

- **원격 호출을 `@Transactional` 안에 넣지 마세요.** user-ms가 2초 늦으면 그동안 DB 연결을 붙잡고 있게 됩니다. 먼저 조회하고, 저장만 트랜잭션으로 합니다.
- `DeliveryErrorCode`는 예시입니다. 팀 규칙대로 common의 `com.common.exception`에 만들고 `ErrorCodeRegistry`에 등록합니다(권우님 규칙).
- user-ms 장애(`RemoteServiceException`·`RemoteTimeoutException`)는 잡지 않았습니다. 그대로 두면 클라이언트에 503·504가 나가고, 담당자를 확인할 수 없으니 배정하지 않는 게 맞습니다.

### ⑥' 쓰는 곳: 상황 B (order-ms, 못 가져와도 진행)

같은 ①~⑤를 order-ms에 만들고(패키지만 `com.order…`), 쓰는 곳에서 **모든 실패를 null로** 바꿉니다.

```java
package com.order.infrastructure.client.user;

@Component
@RequiredArgsConstructor
public class UserSlackIdReader {

    private final UserPort userPort;

    /** 멘션용. 없거나 user-ms 장애면 null → 멘션 없이 알림 */
    public String findSlackIdOrNull(UUID userId) {
        try {
            return userPort.findActiveUser(userId).map(UserInfo::slackId).orElse(null);
        } catch (RemoteServiceException | RemoteTimeoutException | RemoteBusinessException e) {
            return null;
        }
    }
}
```

Slack 알림 전체 흐름은 [[Slack 알림 사용법]] 2·3장을 보세요.

## 4. 상황별로 무슨 일이 일어나나

| user-ms 상태 | `findActiveUser` 결과 | 상황 A (배정) | 상황 B (멘션) |
|---|---|---|---|
| 200, `isDeliveryManager: true` | 값 | 배정 성공 | 멘션 |
| 200, `isDeliveryManager: false` | 값 | 거절 `NOT_DELIVERY_MANAGER` | 멘션 |
| 404 `USER_NOT_FOUND` (없음·탈퇴·비활성) | `Optional.empty()` | 거절 `DELIVERY_MANAGER_NOT_FOUND` | 멘션 없이 |
| 500, user-ms 꺼짐, CB 차단 | `RemoteServiceException` | 클라이언트에 503 | 멘션 없이 |
| 2초 안에 응답 없음 | `RemoteTimeoutException` | 클라이언트에 504 | 멘션 없이 |

조회는 상대 데이터를 바꾸지 않으므로, 응답이 없어도 되돌릴 것이 없습니다. 재고 차감 같은 **변경 호출**은 [[Feign 호출 사용법]] 3·4장의 보상·재시도 규칙을 따르세요.

## 6. 테스트 (3단계)

### 6.1 Facade: 가짜 Port (매 빌드, 가장 빠름)

```java
// 저장 쪽 가짜: 배정이 호출됐는지만 기록
class FakeDeliveryService extends DeliveryService {
    final List<UUID> assigned = new ArrayList<>();
    @Override public void assignManager(UUID deliveryId, UUID managerId, UUID actorId) { assigned.add(managerId); }
}

class DeliveryAssignFacadeTest {

    private final Map<UUID, UserInfo> users = new HashMap<>();
    private final UserPort fakeUserPort = userId -> Optional.ofNullable(users.get(userId));   // 인터페이스가 메서드 하나라 람다로 충분
    private final FakeDeliveryService deliveryService = new FakeDeliveryService();
    private final DeliveryAssignFacade facade = new DeliveryAssignFacade(fakeUserPort, deliveryService);

    @Test
    void 배송담당자가_아니면_거절한다() {
        UUID managerId = UUID.randomUUID();
        users.put(managerId, new UserInfo(managerId, "김일반", false, "U0X"));

        assertThatThrownBy(() -> facade.assignManager(UUID.randomUUID(), managerId, UUID.randomUUID()))
                .isInstanceOfSatisfying(BusinessException.class, e ->
                        assertThat(e.getErrorCode()).isEqualTo(DeliveryErrorCode.NOT_DELIVERY_MANAGER));
        assertThat(deliveryService.assigned).isEmpty();
    }

    @Test
    void user_ms가_죽어_있으면_배정하지_않는다() {
        UserPort down = userId -> { throw new RemoteServiceException("user-ms", 503); };
        DeliveryAssignFacade facadeWhenDown = new DeliveryAssignFacade(down, deliveryService);

        assertThatThrownBy(() -> facadeWhenDown.assignManager(UUID.randomUUID(), UUID.randomUUID(), UUID.randomUUID()))
                .isInstanceOf(RemoteServiceException.class);
        assertThat(deliveryService.assigned).isEmpty();
    }
}
```

### 6.2 Adapter: 진짜 Feign + 가짜 user-ms (WireMock, 매 빌드)

```java
@SpringBootTest
class UserAdapterTest {

    static final WireMockServer USER_MS = new WireMockServer(options().dynamicPort());
    static { USER_MS.start(); }

    @DynamicPropertySource
    static void userMs(DynamicPropertyRegistry registry) {
        // @FeignClient(name = "user-ms")가 Eureka 대신 WireMock으로 가게 한다
        registry.add("spring.cloud.discovery.client.simple.instances.user-ms[0].uri", USER_MS::baseUrl);
    }

    @Autowired UserPort users;                            // 진짜 UserAdapter
    private final UUID userId = UUID.randomUUID();

    @AfterEach void reset() { USER_MS.resetAll(); }
    @AfterAll static void stop() { USER_MS.stop(); }

    @Test
    void 응답_필드를_읽어온다() {
        USER_MS.stubFor(get("/internal/v1/users/" + userId).willReturn(okJson("""
                {"id":"%s","name":"김배송","role":"USER","isDeliveryManager":true,"slackId":"U07ABCDEF1","active":true}
                """.formatted(userId))));

        assertThat(users.findActiveUser(userId)).hasValueSatisfying(user -> {
            assertThat(user.deliveryManager()).isTrue();
            assertThat(user.slackId()).isEqualTo("U07ABCDEF1");
        });
    }

    @Test
    void 없는_사용자는_empty() {
        USER_MS.stubFor(get("/internal/v1/users/" + userId).willReturn(aResponse().withStatus(404)
                .withHeader("Content-Type", "application/json")
                .withBody("""
                        {"code":"USER_NOT_FOUND","message":"사용자를 찾을 수 없습니다."}
                        """)));

        assertThat(users.findActiveUser(userId)).isEmpty();
    }

    @Test
    void user_ms_500은_RemoteServiceException() {
        USER_MS.stubFor(get("/internal/v1/users/" + userId).willReturn(serverError()));

        assertThatThrownBy(() -> users.findActiveUser(userId)).isInstanceOf(RemoteServiceException.class);
    }
}
```

### 6.3 진짜 user-ms와 맞물리는지 (Eureka + 실행 중인 user-ms, 필요할 때만)

[[User·Auth API 사용법]] 5.3의 `UserAdapterE2ETest`를 그대로 씁니다. `@Tag("e2e")`로 평소 빌드에서는 빠지고, Eureka와 user-ms를 띄운 뒤 `-PincludeE2e`로 돌립니다(설정은 [[Feign 호출 사용법]] 7.3).

## 7. 자주 하는 실수

| 증상 | 원인 | 해결 |
|---|---|---|
| 기동 실패 `Feign 클라이언트에 고정 url이 있습니다` | `@FeignClient(url = "http://localhost:19095")` | `url` 빼고 `name = "user-ms"`만 |
| `isDeliveryManager`가 항상 `false` | DTO 필드 이름이 JSON 키와 다름 (`deliveryManager`) | ①처럼 `isDeliveryManager` 그대로 |
| 없는 사용자인데 클라이언트에 404 `USER_NOT_FOUND`가 그대로 나감 | Adapter에서 404를 empty로 바꾸지 않음 | ⑤의 `catch` |
| 로컬에서 계속 503 | user-ms가 꺼져 있거나 Eureka에 아직 등록 전 | http://localhost:8761 에서 `USER-MS` `UP` 확인, 몇 초 뒤 재시도 |
| 테스트에서 `No instances available for user-ms` | 테스트에 주소를 연결하지 않음 | 6.2의 `@DynamicPropertySource` |
| 외부에서 `/internal/v1/users/…`를 부르면 404 | 정상. Gateway가 내부 API를 외부에 숨김 | 서비스끼리 Feign으로만 부르고, 로컬 확인은 user-ms 포트(19095)로 |
| 응답에 `username`·소속이 필요함 | 내부 API에 없는 필드 | 대진에게 요청 (user-ms 응답과 ①을 함께 바꿈) |
