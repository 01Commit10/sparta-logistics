## 1. 준비

| 항목 | 확인 방법 |
|---|---|
| Docker Desktop 실행 | `docker info`가 오류 없이 나와야 함 |
| Java 21 | `java -version` |
| Python 3 (선택) | 개발용 토큰 스크립트 `scripts/dev-token.py`를 쓸 때만 (표준 라이브러리만 사용, 설치 불필요) |
| `.env` (프로젝트 루트) | `.env.example`을 복사해 값 채우기. **Git에 올리지 않음** |

**`.env`에 넣을 값**

```properties
DB_NAME=sparta_logistics
DB_PORT=5432
# DB_HOST=localhost                  # 생략 시 localhost
# DDL=update  SHOW_SQL=false         # 선택 (기본값 그대로 써도 됨)
DB_USER=sparta_admin                 # Postgres 관리자 (컨테이너용, 서비스는 사용 안 함)
DB_PASSWORD=...
AUTH_DB_USER=auth_svc                # 서비스별 DB 계정
AUTH_DB_PASSWORD=...
# HUB_/COMPANY_/ORDER_/DELIVERY_ 도 같은 형식

REDIS_HOST=localhost
REDIS_PORT=6379
REDIS_PASSWORD=...                   # openssl rand -hex 24 (없으면 Compose가 Redis를 띄우지 않음)

JWT_SECRET_KEY=...                   # openssl rand -base64 32 (Gateway·user-ms가 같은 값을 읽음)

# 초기 MASTER — .env.example에는 아직 없습니다. 직접 추가하세요
MASTER_USERNAME=master01             # 4~10자 소문자·숫자
MASTER_PASSWORD=...                  # 8~15자, 대·소문자·숫자·특수문자 모두 포함
MASTER_NAME=관리자
MASTER_SLACK_ID=...

# Slack 알림 (선택. 비워 두면 알림을 보내지 않음. 넣어 두면 통합 테스트도 실제로 보낼 수 있음 → 05 통합 테스트 가이드 5.1)
# SLACK_WEBHOOK_URL=
```

> `DB_*` 값을 바꾸면 기존 `./pgdata`를 지우고 DB를 다시 만들어야 합니다(초기화 스크립트는 처음 한 번만 실행됨).

## 2. 실행 순서

```bash
# 1) PostgreSQL·Redis (처음 한 번은 아래 "알려진 문제 1" 확인)
docker compose up -d postgres redis

# 2) Eureka → 3) 서비스 → 4) Gateway (터미널을 나눠서)
sh ./gradlew :eureka-registry:bootRun
sh ./gradlew :user-ms:bootRun          # 확인할 서비스만 추가로 띄웁니다
sh ./gradlew :gateway-edge:bootRun
```

- `./gradlew`가 "permission denied"면 `sh ./gradlew`로 실행합니다(알려진 문제 2).
- IntelliJ에서는 각 `*Application`을 Run 해도 됩니다. 작업 디렉터리가 모듈 폴더여도 `../.env`를 읽습니다.
- **Redis는 필수입니다.** Gateway는 모든 보호 경로에서 Redis로 로그아웃 여부를 확인하므로, Redis가 없으면 503 `AUTH_UNAVAILABLE`입니다.

**포트**

| 서비스 | 포트 | 서비스 | 포트 |
|---|---|---|---|
| Eureka | 8761 | hub-ms | 19093 |
| **Gateway** | **19090** | order-ms | 19094 |
| company-ms | 19091 | user-ms | 19095 |
| delivery-ms | 19092 | PostgreSQL / Redis | 5432 / 6379 |

**기동 확인**

| 확인 | 주소 | 기대 결과 |
|---|---|---|
| Eureka 대시보드 | http://localhost:8761 | `GATEWAY-EDGE`, `USER-MS`가 `UP` |
| user-ms 헬스 | http://localhost:19095/actuator/health | `UP` (Redis·DB 포함) |
| Gateway 헬스 | http://localhost:19090/actuator/health | `UP` (Redis 포함) |
| 서비스 직접 호출 | http://localhost:19095/api/v1/auth/routing-check | 200 |
| Gateway 경유 호출 | 로그인 토큰을 붙여 http://localhost:19090/api/v1/auth/routing-check | 200 (기동 직후 잠깐 503일 수 있음 → 4장) |

**초기 MASTER 확인 (USR-19)**: `.env`에 `MASTER_*`를 넣고 user-ms를 기동하면 로그에 `[InitialMaster] 초기 MASTER를 생성했습니다. username=…`가 나오고 `auth.p_users`에 MASTER 1명이 생깁니다. 재기동해도 늘지 않습니다. 값이 비어 있으면 경고 로그만 남기고 기동합니다.

## 3. 직접 확인해 보기

### 3.1 Postman (권장)

1. Postman → Import → `docs/postman/sparta-logistics-gateway.postman_collection.json` (요청 56개)
2. Collection Runner로 **위에서부터 순서대로** 실행합니다. 회원가입 → 로그인 → 로그아웃 → 재발급 → 내 정보 → 비밀번호 변경 → 탈퇴까지 토큰을 자동으로 이어받습니다.
3. `masterToken`·`userToken`·`expiredToken`만 직접 채웁니다. 방법과 요청별 기대 결과는 [[Postman Gateway 테스트 가이드]] 2.3·4장.

> 10/16 확인: `feat/user-me`(U09~U11) + Redis 기동 상태에서 50개 전체 PASS. 이후 GW-08(51·52)·경로 정규화(53~56) 추가, 56개 전체 PASS.

### 3.2 curl

```bash
# 로그인 (공개 경로) → accessToken 꺼내기
TOKEN=$(curl -s localhost:19090/api/v1/auth/login -H 'Content-Type: application/json' \
  -d '{"username":"<MASTER_USERNAME>","password":"<MASTER_PASSWORD>"}' | python3 -c 'import sys,json;print(json.load(sys.stdin)["accessToken"])')

curl -s localhost:19090/api/v1/auth/routing-check -H "Authorization: Bearer $TOKEN"   # 200
curl -s localhost:19090/api/v1/users/me          -H "Authorization: Bearer $TOKEN"   # 내 정보

# 로그인으로 만들 수 없는 토큰(만료 등)은 개발용 스크립트로
curl -s localhost:19090/api/v1/users -H "Authorization: Bearer $(python3 scripts/dev-token.py)"   # USER → 403
```

- zsh에서는 `?`가 들어간 URL을 따옴표로 감쌉니다(`'localhost:19090/api/v1/auth/check-username?username=user01'`).
- `scripts/dev-token.py` 옵션: `--role MASTER|USER`, `--user-id <UUID>`, `--pcr`, `--ttl <분>`, `--typ`, `--expired`. 같은 루트 `.env`의 `JWT_SECRET_KEY`로 서명합니다.

### 3.3 확인용 엔드포인트 `GET /api/v1/auth/routing-check` (user-ms)

```json
{
  "service": "user-ms",
  "method": "GET",
  "path": "/api/v1/auth/routing-check",
  "query": "from=postman",
  "headers": { "X-User-Id": "…", "X-User-Role": "MASTER", "X-Token-Jti": "…", "X-Token-Exp": "…" }
}
```

- 받은 요청의 경로·메서드와 Gateway 관련 헤더(`X-User-*`, `X-Token-*`, `X-Request-Id`, `X-Forwarded-*`)만 돌려줍니다. `Authorization`·`Cookie`는 돌려주지 않습니다.
- **토큰이 필요합니다.** 응답 `headers`에서 Gateway가 넣은 값을 확인할 수 있습니다.
- 개발 확인용입니다. 제출·운영 시에는 `ROUTING_CHECK_ENABLED=false`(`app.routing-check.enabled`)로 끕니다.

## 4. 문제 해결

| 증상 | 원인 | 해결 |
|---|---|---|
| Gateway 경유가 503 `SERVICE_UNAVAILABLE`인데 서비스 직접 호출은 200 | Gateway가 아직 Eureka에서 서비스를 못 받아옴 (조회 주기·LB 캐시 5초) | 5~30초 기다림 |
| 모든 Gateway 요청이 503 `SERVICE_UNAVAILABLE` | Eureka 미기동 또는 서비스 미등록 | Eureka 대시보드에서 등록 확인 |
| 보호 경로가 전부 503 `AUTH_UNAVAILABLE` | Gateway가 Redis에 접속하지 못함 (미기동·`REDIS_PASSWORD` 불일치) | `docker compose up -d redis`, `.env` 확인 후 Gateway 재기동 |
| 로그인·재발급·로그아웃이 503 `AUTH_UNAVAILABLE` | user-ms가 Redis에 접속하지 못함 | 위와 같음 |
| Gateway·user-ms `/actuator/health`가 `DOWN` | Redis(또는 DB) 접속 실패. 헬스에 Redis가 포함됨 | 위와 같음. 헬스 그룹 분리는 GW-11(예정) |
| 30분쯤 지나 모든 요청이 401 `TOKEN_EXPIRED` | Access Token 만료(30분) | `POST /api/v1/auth/reissue` 또는 다시 로그인 |
| 401 `TOKEN_REVOKED` | 로그아웃·비밀번호 변경·탈퇴한 뒤 이전 토큰을 씀 | 다시 로그인 |
| 401 `TOKEN_INVALID`인데 토큰은 방금 받음 | Gateway와 user-ms(또는 스크립트)가 다른 `JWT_SECRET_KEY`를 읽음 | 같은 루트 `.env`, 값을 바꿨다면 **둘 다** 재기동 |
| 서비스 직접 호출이 401 `UNAUTHENTICATED` | `X-User-Id`·`X-User-Role` 중 하나만 넣었거나 형식이 틀림 | 둘 다 넣거나 둘 다 빼기([[01 Gateway·인증 가이드]] 9장) |
| Postgres 컨테이너가 바로 종료, 로그에 `bad interpreter: Permission denied` | 알려진 문제 1 | 아래 참고 |
| `./gradlew: permission denied` | 알려진 문제 2 | `sh ./gradlew` |
| 서비스 기동 실패 `password authentication failed` | ① `.env`의 DB 값과 `pgdata`에 만들어진 계정이 다름 | `docker compose down && rm -rf pgdata` 후 다시 `up` |
| (같은 오류) `.env`를 **환경 변수로** 넣었을 때만 실패 (IntelliJ EnvFile, `set -a; . ./.env`, Compose `env_file`) | ② 알려진 문제 3 | `.env`는 환경 변수로 넣지 말고 Spring이 파일로 읽게 둠 |

**알려진 문제** (권우님께 공유, 2026-10-16 현재 그대로)

1. `docker/postgres/init/01-init-service-accounts.sh`가 Git에 실행 권한 없이(`100644`) 저장되어 있어 DB 초기화가 실패합니다.
   - 임시 해결: `chmod +x docker/postgres/init/01-init-service-accounts.sh` → `rm -rf pgdata` → `docker compose up -d postgres` → (DB 생성 후) `chmod -x …`로 되돌림
   - 근본 해결: `git update-index --chmod=+x docker/postgres/init/01-init-service-accounts.sh`
2. `gradlew`도 같은 이유로 실행 권한이 없습니다(`100644`). 근본 해결: `git update-index --chmod=+x gradlew`
3. **`.env`의 `DB_PASSWORD`(Postgres 관리자)가 환경 변수로 들어오면 서비스의 `db.password`를 덮어씁니다.**
   - Spring은 환경 변수 `DB_PASSWORD`를 속성 `db.password`로 읽습니다(relaxed binding). 환경 변수가 yaml의 `db.password: ${AUTH_DB_PASSWORD}`보다 우선이라, 서비스가 관리자 비밀번호로 접속하다 실패합니다.
   - Spring이 `.env` **파일**을 읽을 때(`spring.config.import: optional:file:.env[.properties]`)는 이 변환이 없어 문제가 없습니다.
   - Compose로 서비스 컨테이너를 띄울 때 `env_file: .env`를 쓰면 모든 서비스가 같은 문제를 겪습니다(GW-01 컨테이너화 때 함께 해결 필요).
   - 근본 해결(권우님 결정): `.env` 관리자 변수를 `POSTGRES_ADMIN_USER`/`POSTGRES_ADMIN_PASSWORD`처럼 바꾸거나, 서비스 yaml 키 `db.username`/`db.password`를 겹치지 않는 이름으로 변경
4. `.env.example`에 `MASTER_*`가 없습니다. 1장 예시처럼 직접 추가합니다.

## 5. 자동 테스트

```bash
sh ./gradlew :gateway-edge:test         # Gateway (Docker 불필요)
sh ./gradlew :user-ms:test              # user-ms (H2)
sh ./gradlew :common:test               # common (WireMock)
sh ./gradlew :user-ms:test -PincludeContainer   # Docker가 필요한 테스트까지 (@Tag("container"), Testcontainers)
```

- **모듈별로 실행하세요.** 루트 `sh ./gradlew test`는 hub-ms `contextLoads`가 H2에서 Postgres 전용 시드(`db/seed/hubs.sql`)를 실행하다 실패할 수 있습니다(이찬님 확인 중).
- `-PincludeContainer`는 `gateway-edge`, `user-ms`에서 지원합니다.
- 통합 테스트 작성법(WireMock으로 다른 서비스 흉내 내기, Testcontainers, 장애 시나리오)은 [[05 통합 테스트 가이드]]를 보세요.
